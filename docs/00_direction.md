# 方向性：入会手続きのデジタル化

対象：パーソナルジム「絆 Style-gym Legame 琴似店」の入会手続き

## 1. 前提

- 会員プランは「通い放題（フリー利用）＋パーソナルトレーニング」を組み合わせた仕組みで、説明が必要。
- 入会の流れは **体験 → その場で入会手続き**。手続きはこの場で必ず完結させる。
- 事前の Web 申込は**作らない**（実績がほとんどなく、プランが複雑なため対面での説明が前提）。
- 法律上必須の書面ではないが、後々のトラブルを防ぐために、会員契約書とご入会のしおりを用意している。
- しおりの全文は Legame 公式アプリで閲覧できる。
- お支払いは目の前で案内する。
  - 口座振替：アプラスの口座振替依頼書（紙・銀行印）
  - クレジットカード：ペイジェントの登録 URL を LINE で送り、お客様が登録

## 2. 契約書のオンライン化（決定）

**MF クラウド契約を使う。**今の MF クラウドの契約で利用できることは確認済み。

- お客様が自分のスマホで署名する。締結済みの契約書は MF に保管され、お客様にも控えが届く。
- スマホやメールが使えないお客様は紙で契約し、顧客管理名簿に「紙での契約書」と記入する。

**要確認**
- 月あたりの送信件数の上限・超過時の費用
- 従業員アカウントの追加と権限設定

## 3. 重要事項のチェック（検討中）

**第1案：契約書の中でチェックする（フォームは使わない）**

- 会員契約書の最後に「重要事項の確認」ページを追加し、MF クラウド契約で各項目に必須のチェック欄を置く。内容の案は `e-contract/important-checks.md`。
- 長所：手順が1つ減る。チェック結果が締結済みの契約書の中に残るので、証跡として強い。控えも自動でお客様に届く。紙で契約する場合も同じページを印刷すれば使える。
- **要確認**：MF クラウド契約で、チェックボックスを「必須」にして、チェックしないと署名できない設定ができるか。テスト送信で確かめる。

**第2案（第1案ができない場合）：Google フォーム**

- 契約締結後、チェック用フォームの URL を LINE で送り、回答をスプレッドシートに自動記録する。控えはメールで送る。
- 作成スクリプト：`member-guide/gas/createGuideForm.gs`

## 4. Web 版しおり（新規の案）

入会のお礼として、しおりを読みやすい Web ページ（漫画風・会話形式など）にして、URL を LINE で送る。

- 公式アプリのしおり（正式版）とは別の、「読みやすい案内」という位置付け。規約の正式な内容は契約書・会員規約が優先。
- 公開ページになるため、Wi-Fi パスワードなど店内限定の情報は載せない。

## 5. 入会手続き当日の流れ（目標）

1. 体験
2. コース・オプションの説明
3. 店内の Wi-Fi に接続してもらう
4. **電子契約**：MF から送信 → お客様がスマホで重要事項にチェックして署名
5. Legame 公式アプリ・公式 LINE・れんらくアプリの登録
6. お支払いの案内（口座振替依頼書の記入、またはペイジェントの URL を LINE で送付）
7. 身分証コピー・写真撮影・お会計・会員証のお渡し
8. 後日（または当日中）：入会のお礼と Web 版しおりの URL を LINE で送る

## 6. 未決事項

- Web 版しおりの公開場所（Google サイト、GitHub Pages など）と、絵の作り方
